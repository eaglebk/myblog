# Грабли дня: два CryptoProvider в rustls и паника на ровном месте

> Почему сервер на Rust может спокойно стартовать, а потом упасть на первом же TLS-соединении, и как одной строкой в main() выбрать криптобэкенд для rustls.

Сегодня в рубрике - **`rustls`** и его `CryptoProvider`. Эту ошибку не ловят ни компилятор, ни `clippy`, ни локальные тесты.

---

## Как это выглядело

Я добавил в свой бэкенд на Axum отправку писем с кодом входа через крейт `mail-send` (SMTP + STARTTLS + DKIM). Локально `cargo clippy` прошёл без единого предупреждения, Docker-образ собрался, деплой прошёл, healthcheck вернул `200 OK`.

Но первый же запрос на отправку кода вернул:

```text
HTTP/1.1 502 Bad Gateway
Server: nginx/1.24.0 (Ubuntu)
```

А в логах сервера была паника:

```text
thread 'tokio-rt-worker' panicked at rustls-0.23.46/src/crypto/mod.rs:249:14:

Could not automatically determine the process-level CryptoProvider from Rustls crate features.
Call CryptoProvider::install_default() before this point to select a provider manually,
or make sure exactly one of the 'aws-lc-rs' and 'ring' features is enabled.
```

---

## Что такое CryptoProvider

Раньше `rustls` всегда брал всю криптографию (рукопожатие TLS, AES-GCM, ChaCha20, подписи) из крейта **`ring`**.

Начиная с версии **0.23** криптобэкенд вынесли за интерфейс `CryptoProvider`, и выбирать его можно через фичи:

- **`ring`** - классическая компактная криптобиблиотека (Rust + ассемблер);
- **`aws-lc-rs`** - криптография от AWS на базе форка BoringSSL, с режимом FIPS. Именно её `rustls` сейчас включает по умолчанию.

{{< alert "comment" >}}
**CryptoProvider** - это структура с набором реализаций: шифры, алгоритмы обмена ключами, проверка подписей, генератор случайных чисел. `rustls` реализует сам протокол TLS, а все математические операции делегирует провайдеру.
{{< /alert >}}

Если в бинарник попала **только одна** из фич, `rustls` сам выбирает её как провайдер по умолчанию, и разработчик ничего не замечает.

---

## Откуда взялись два провайдера

Главная причина - **объединение фич в Cargo (feature unification)**. Если несколько зависимостей тянут один и тот же крейт с разными фичами, Cargo собирает **одну** копию этого крейта со **всеми фичами сразу**.

В моём проекте получилось так:

- `aws-sdk-s3` (работа с MinIO / S3) включил в `rustls` фичу **`aws-lc-rs`**;
- новый `mail-send` включил фичу **`ring`**.

В итоге в одном `rustls` оказались оба бэкенда. Угадывать, какой из них нужен, `rustls` **специально отказывается**. Иначе сервис, которому важен FIPS-режим `aws-lc-rs`, мог бы молча переключиться на `ring`. Поэтому `rustls` паникует и просит выбрать провайдер явно.

Посмотреть, кто какую фичу включает, можно так:

```bash
cargo tree -e features -i rustls@0.23.46
```

{{< alert "lightbulb" >}}
Флаг `-i` (invert) показывает дерево «снизу вверх»: от `rustls` к тем зависимостям, которые его подключили. С `-e features` в выводе видно, какая именно зависимость включила `ring`, а какая `aws-lc-rs`.
{{< /alert >}}

## Почему не упало сразу при старте

Провайдер ищется **лениво**, в момент первого создания TLS-конфига (`ClientConfig::builder()`).

На старте мой сервер подключался к Postgres и MinIO внутри Docker-сети **без TLS**, поэтому `rustls` вообще не вызывался. Первый TLS появился, только когда `mail-send` начал STARTTLS с почтовым сервером получателя. В этот момент воркер `tokio` упал, соединение оборвалось, и `nginx` честно ответил `502`.

{{< alert "fire" >}}
Такая ошибка может месяцами спать в коде и проснуться на первом HTTPS-запросе к внешнему API. Healthcheck, который проверяет только «процесс жив и отвечает», её не заметит.
{{< /alert >}}

## Решение в одну строку

Нужно установить провайдер для всего процесса **до** создания любых TLS-соединений, то есть первой строкой в `main()`:

```rust
#[tokio::main]
async fn main() -> anyhow::Result<()> {
    // Выбираю криптобэкенд для rustls на весь процесс
    let _ = rustls::crypto::ring::default_provider().install_default();

    // ...дальше логгер, пул БД, S3, HTTP-сервер
    Ok(())
}
```

Чтобы обратиться к `rustls::crypto::ring`, добавляю `rustls` как прямую зависимость:

```toml
[dependencies]
rustls = { version = "0.23", default-features = false, features = ["ring"] }
```

Пара нюансов:

1. **Почему `let _ =`.** `install_default()` возвращает `Err`, если провайдер уже установлен (например, его успела поставить какая-то библиотека). Для меня это не ошибка, поэтому результат просто игнорирую.
2. **Тесты.** У `#[tokio::test]` своя точка входа, `main()` там не вызывается. Если в тестах есть TLS, вызов `install_default()` нужно добавить и в тестовый хелпер. Повторный вызов безопасен, он просто вернёт `Err`:

   ```rust
   fn init_crypto() {
       let _ = rustls::crypto::ring::default_provider().install_default();
   }

   #[tokio::test]
   async fn sends_login_code() {
       init_crypto();
       // ...тест, который ходит в SMTP или HTTPS
   }
   ```

3. **Альтернатива.** Можно выровнять фичи так, чтобы все зависимости использовали один бэкенд (например, только `aws-lc-rs`). Но в большом дереве зависимостей это хрупко: следующий `cargo add` снова может притащить второй провайдер. Явный `install_default()` надёжнее.

Если нужен FIPS или просто хочется остаться на дефолтном бэкенде `rustls`, в той же строке можно выбрать `aws-lc-rs`: `rustls::crypto::aws_lc_rs::default_provider().install_default()`. Главное - выбрать явно.

## Выводы

1. **Фичи в Cargo складываются**, а не выбираются: любая новая зависимость может поменять поведение уже подключённого крейта.
2. **`rustls` 0.23+ с двумя провайдерами паникует в рантайме**, а не при компиляции, и только на первом TLS-соединении.
3. **Явно выбирайте `CryptoProvider` в `main()`**, если в проекте много сетевых зависимостей (AWS SDK, `reqwest`, `sqlx`, `tonic`, SMTP-клиенты). Одна строка избавит от загадочных `502` в проде.

**2. Когда rustls 0.23 паникует, если включены оба провайдера и ни один не установлен явно?**

- [ ] На этапе компиляции
- [ ] Сразу при запуске программы
- [ ] При первом создании TLS-конфига, например ClientConfig::builder()
- [ ] Только при завершении процесса

**3. Почему результат install_default() в примере игнорируется через let _ = ?**

- [ ] Функция возвращает Err, если провайдер уже установлен, и это не считается ошибкой
- [ ] Функция всегда возвращает (), а let _ нужен для красоты
- [ ] Иначе компилятор не даст вызвать функцию в async-контексте
- [ ] Так провайдер устанавливается только для текущего потока

**4. Почему rustls не выбирает один из провайдеров сам, когда включены оба?**

- [ ] Потому что ring и aws-lc-rs несовместимы и не могут жить в одном бинарнике
- [ ] Чтобы сервис, которому важен, например, FIPS-режим aws-lc-rs, не переключился молча на другой бэкенд
- [ ] Потому что это баг, который исправят в следующей версии
- [ ] Потому что выбор провайдера возможен только через переменную окружения

**5. Какая команда покажет, какие зависимости включают фичи в rustls?**

- [ ] cargo check --features rustls
- [ ] cargo tree -e features -i rustls
- [ ] cargo metadata --rustls
- [ ] cargo clippy -- -W features

**6. Нужно ли вызывать install_default() в тестах с #[tokio::test], если он уже есть в main()?**

- [ ] Нет, main() выполняется перед каждым тестом
- [ ] Да, у тестов своя точка входа, и main() там не вызывается
- [ ] Нет, в тестах rustls всегда использует ring
- [ ] Да, но только для тестов без async
