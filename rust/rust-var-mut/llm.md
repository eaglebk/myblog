## Введение

В большинстве популярных языков программирования (JavaScript, Python, C++, Java) переменные по умолчанию являются изменяемыми: объявив переменную, вы можете в любой момент присвоить ей новое значение. 

В Rust создатели языка пошли по принципиально иному пути: **все переменные по умолчанию являются иммутабельными (неизменяемыми)**. Если вам нужно изменить значение переменной в процессе работы программы, это намерение требуется выразить явно с помощью ключевого слова `mut`.

В этой статье я разберу, как работает ключевое слово `mut`, почему неизменяемость по умолчанию делает код надежнее и в чем разница между мутабельностью и затенением (Shadowing).

## Неизменяемость на практике: обещание себе

Давайте рассмотрим простой жизненный пример. Предположим, я решил составить режим дня: вставать в 6 утра и ложиться спать в 22:00. Для этого я создаю две переменные, вывожу их в консоль, а затем пробую изменить значения.


### 💻 Изменяемые и неизменяемые переменные в Rust


#### Шаг 1

```rust
// ?compile_fail
fn main() {
    let get_up = 6;
    let bedtime = 22;
    println!("Я планирую вставать в {} часов и ложиться спать в {}", get_up, bedtime);

    get_up = 7; // ❌ Ошибка компиляции: get_up неизменяема
    bedtime = 23;
}
```

**Попытка изменить неизменяемую переменную**
- В Rust переменные по умолчанию неизменяемы (immutable).
- Этот код приведёт к ошибке компиляции E0384.


#### Шаг 2

```rust
fn main() {
    let mut get_up = 6;
    let mut bedtime = 22;
    println!("Я планирую вставать в {} часов и ложиться спать в {}", get_up, bedtime);

    get_up = 7; // ✅ Корректно: переменные помечены как `mut`
    bedtime = 23;

    println!("Я планирую вставать в {} часов и ложиться спать в {}", get_up, bedtime);
}
```

**Использование ключевого слова mut**
- Чтобы сделать переменную изменяемой, добавьте `mut` после `let`.
- Теперь значения переменных можно безопасно переопределять.


### Анализ ошибки E0384

На первом шаге компилятор незамедлительно пресекает попытку сборки и выдает ошибку:

```text
error[E0384]: cannot assign twice to immutable variable `get_up`
 --> src/main.rs:7:5
  |
3 |     let get_up = 6;
  |         ------ first assignment to `get_up`
...
7 |     get_up = 7;
  |     ^^^^^^^^^^ cannot assign twice to immutable variable
```

Компилятор четко объясняет: переменная `get_up` неизменяема, поэтому повторное присваивание недопустимо. 

### Решение: явное объявление через mut

Чтобы разрешить перезапись значения, я добавляю ключевое слово `mut` сразу после `let`:

```rust
let mut get_up = 6;
get_up = 7; // Теперь компилятор одобряет операцию
```

Добавляя `mut`, я даю явный сигнал и компилятору, и любому человеку, который будет читать мой код: *«Внимание, значение этой переменной будет меняться в процессе выполнения блока»*.

## Почему именно иммутабельность по умолчанию?

На первых порах необходимость везде ставить `mut` может казаться излишней строгостью. Но за этим архитектурным решением стоят три фундаментальные причины:

### 1. Безопасность и предсказуемость логики

Когда я читаю большой фрагмент кода функции на 50–100 строк, мне не нужно держать в голове возможность внезапного изменения переменной, если возле нее нет ключевого слова `mut`. Я уверен, что значение, присвоенное при инициализации, останется неизменным до самого выхода из области видимости. Это исключает целый класс скрытых багов, когда переменная случайно перезаписывается внутри вложенного цикла или условия.

### 2. Защита от состояний гонки (Data Races)

Rust изначально проектировался для надежного параллельного и асинхронного программирования. Главный источник проблем в многопоточных программах — одновременная несогласованная мутация общих данных. 

Если данные неизменяемы, сотни параллельных потоков могут безопасно читать их одновременно без использования тяжелых блокировок, семафоров и мьютексов.

### 3. Оптимизации компилятора и LLVM

Когда компилятор `rustc` точно знает, что значение переменной не меняется, он может применить агрессивные низкоуровневые оптимизации:
- Разместить значение непосредственно в быстром регистре CPU вместо постоянных обращений в память стека.
- Применить свертку констант (Constant Folding) — вычислить результат выражений еще на этапе компиляции бинарника.

## Мутабельность структур и коллекций

Важное правило языка Rust: **мутабельность не бывает частичной**.

Если я создаю пользовательскую структуру или вектор, я не могу объявить изменяемым только одно поле:

```rust
struct SensorData {
    id: u32,
    value: f32,
}

// Так сделать нельзя:
// struct SensorData { id: u32, mut value: f32 }

// Мутабельность задается для всей структуры целиком:
let mut sensor = SensorData { id: 1, value: 24.5 };
sensor.value = 25.1; // Разрешено, так как экземпляр sensor объявлен как mut
```

То же самое касается и стандартных коллекций: чтобы добавлять элементы в вектор через `push()`, сам вектор обязан быть помечен как `mut`:

```rust
let mut readings = Vec::new();
readings.push(10);
readings.push(20);
```

## Мутабельность vs Затенение (Shadowing)

В Rust часто возникает вопрос: когда использовать `let mut`, а когда — повторное объявление через `let` (механизм затенения)?

| Критерий | `let mut x = ...` (Мутабельность) | `let x = ...; let x = ...;` (Затенение) |
| :--- | :--- | :--- |
| **Смена типа** | Запрещена (тип фиксируется при создании) | Разрешена (можно изменить тип на лету) |
| **Случайные мутации** | Переменная остается изменяемой дальше | Каждая новая переменная неизменяема |
| **Назначение** | Накопление значений в цикле, счетчики, буферы | Пошаговая трансформация и валидация данных |

Например, при трансформации строкового ввода в число затенение гораздо чище и безопаснее мутабельности:

```rust
let spaces = "   ";          // Тип &str
let spaces = spaces.len();   // Тип usize (затенение изменило тип и осталось неизменяемым!)
```

Подробнее о том, как работает затенение и как оно экономит память, я рассказывал в статье [Затенение переменных (Shadowing) в Rust](../rust-shadowing/).

## Итоги

1. Все переменные в Rust по умолчанию **неизменяемы (immutable)**.
2. Ключевое слово `mut` ставится сразу после `let` и явно разрешает изменение значения.
3. `mut` разрешает менять значение, но **не позволяет менять тип** переменной.
4. Иммутабельность обеспечивает потокобезопасность и помогает компилятору оптимизировать бинарный файл.
