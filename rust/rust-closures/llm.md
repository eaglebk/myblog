- **Tags:** rust, dev, closures, advanced

---
В повседневном коде на Rust замыкания встречаются на каждом шагу: от простых цепочек итераторов `.map(|x| x * 2)` и `.filter(|item| item.id == target_id)` до запуска фоновых задач в `tokio::spawn(async move { ... })`. На первый взгляд это обычные лямбды, знакомые по десятку других языков. Пишешь аргументы в вертикальных чертах `|...|`, обращаешься к нужным переменным снаружи, и всё работает.

Интересное начинается тогда, когда вы пытаетесь сохранить такое замыкание в структуру, вернуть его из функции или передать в другой поток.

В языках со сборщиком мусора (Go, JavaScript, Python, C#) рантайм решает проблему локальных переменных просто: если замыкание обращается к внешней переменной, она тихо переезжает со стека в кучу и живёт там, пока на неё кто-то да ссылается. 

В Rust сборщик мусора отсутствует. Если лямбда обращается к переменной из стека, компилятор обязан ещё при сборке понять три вещи: берёт ли она данные по обычной ссылке (`&T`), по изменяемой (`&mut T`) или забирает во владение (`T`), кто освободит эту память и как долго само замыкание будет жить.

Из-за этого в языке нет единого универсального типа **функция**. Вместо него есть простые указатели `fn` и три разных типажа: `FnOnce`, `FnMut` и `Fn`. Попробуем в этом разобраться и понять как вся эта механика устроена внутри компилятора.

---

## 1. Обычные указатели на функции (`fn`)

Начнём с самого простого случая, когда никакой внешней памяти функции не нужно.

У любой обычной функции в скомпилированном бинарнике есть фиксированный адрес в сегменте кода (`.text`), где находится первая машинная инструкция этой функции. В Rust имя функции работает как указатель на этот адрес, а его тип записывается со строчной буквы: например, `fn(i32) -> i32`.

Такой `fn` весит ровно 8 байт (размер обычного указателя на 64-битной платформе). Никаких внешних переменных он не видит и работает только со своими аргументами.

Допустим, я хочу написать свою простую функцию `map` для срезов, которая принимает указатель `fn(T) -> U`:

```rust
fn map<T, U>(slice: &[T], func: fn(T) -> U) -> Vec<U>
where
    T: Copy,
{
    let mut result = Vec::with_capacity(slice.len());
    for value in slice {
        // value имеет тип &T, поэтому разыменовываем его (*value) перед вызовом
        result.push(func(*value));
    }
    result
}
```

Пока я передаю в `map` обычную функцию или простое замыкание без внешних переменных вроде `|x| x * 2`, компилятор доволен и не ругается. Более того, замыкания, которые вообще ничего не захватывают из окружения, автоматически приводятся к обычному указателю `fn`.

Но стоит написать снаружи `let factor = 10;` и попробовать передать `|x| x * factor` в аргумент типа `fn(i32) -> i32`, как сборка тут же упадёт. И причина тут такая: указатель `fn` хранит только 8 байт адреса кода. Положить саму переменную `factor` (или ссылку на неё) просто некуда.

## 2. Как замыкание захватывает переменные и зачем нужен `move`

Чтобы функция могла запоминать что находится во внешних переменных, ей кроме адреса кода нужен собственный кусок памяти под данные:

```rust
let coefficient = 10;
let multiply = |x| x * coefficient;
```

Типы аргументов и возвращаемого значения внутри `|...|` почти никогда не указывают вручную. Компилятор смотрит на первый вызов `multiply(5)` и сам выводит сигнатуру `|x: i32| -> i32` (хотя при желании типы можно указать явно).

Куда интереснее то, как именно `multiply` обращается к внешней переменной `coefficient`. Компилятор смотрит, что вы делаете с переменной внутри замыкания, и берёт ровно столько прав, сколько нужно:

1. Если внутри замыкания переменная только читается (выводится через `println!`, складывается, передаётся по `&T`), замыкание просто берёт неизменяемую ссылку `&coefficient`.
2. Если переменная внутри изменяется (например, у вектора вызывается `list.push(x)` или к счётчику прибавляется единица), замыкание берёт изменяемую ссылку `&mut list`. Пока такое замыкание существует, никто другой к `list` обратиться не сможет.
3. Если переменную внутри замыкания удаляют или отдают по значению в другую функцию (например, вызывают `drop(data)` или `data.into_iter()`), одной ссылки уже мало, поэтому замыкание переносит `data` внутрь себя целиком.

Казалось бы, если компилятор сам понимает, когда нужна ссылка, а когда перенос владения, зачем в языке отдельное ключевое слово `move`?

Оно нужно в тех случаях, когда внутри замыкания переменная только читается (и компилятор по умолчанию взял бы обычную ссылку `&T`), но само замыкание будет **жить дольше текущей функции**. Типичный пример: вы возвращаете замыкание наружу или отправляете его в фоновый поток через `std::thread::spawn`:

```rust
let data = vec![1, 2, 3];

std::thread::spawn(move || {
    // Внутри мы только читаем data, но без слова move компилятор взял бы &data.
    // Поток может работать дольше текущей функции, поэтому ссылка на стек недопустима.
    println!("Данные в потоке: {:?}", data);
});
```

Ключевое слово `move` перед аргументами запрещает брать ссылки и заставляет замыкание перенести все используемые переменные внутрь себя по значению.

> [!NOTE]
> Небольшой подвох со словом `move`, на котором часто спотыкаются на собеседованиях: если захваченная переменная реализует типаж `Copy` (например, обычный `i32` или `bool`), то при `move` внутрь замыкания попадает её побитовая копия. Оригинальная переменная снаружи при этом остаётся полностью рабочей и доступной.

## 3. Что компилятор генерирует под капотом

Прежде чем разбираться с типажами `Fn`, `FnMut` и `FnOnce`, полезно один раз увидеть, во что компилятор превращает замыкание при сборке. Никакой особой магии в рантайме там нет.

Когда вы пишете:

```rust
let factor = 10;
let multiply = |x: i32| x * factor;
```

компилятор прямо на месте генерирует невидимую анонимную структуру, полями которой становятся все захваченные переменные, а сам код замыкания превращает в метод этой структуры:

```rust
// Псевдокод того, что генерирует rustc:
struct ClosureEnvironment<'a> {
    factor: &'a i32, // или просто i32, если было использовано слово move
}

impl<'a> ClosureEnvironment<'a> {
    fn call(&self, x: i32) -> i32 {
        x * (*self.factor)
    }
}
```

Именно из этого простого факта вытекают все правила работы с замыканиями в Rust:

- У каждого замыкания в коде свой уникальный анонимный тип структуры. Даже если вы напишете на соседних строчках два абсолютно одинаковых замыкания `|x| x + 1`, для компилятора это две разные структуры с разными типами.
- Размер замыкания на стеке равен сумме размеров тех переменных (или ссылок), которые оно захватило. Если замыкание ничего не захватывает, его структура имеет нулевой размер (ZST, 0 байт).

## 4. Три типажа: FnOnce, FnMut и Fn

Посмотрите ещё раз на метод `call(&self, ...)` у сгенерированной структуры выше. Как и любой обычный метод в Rust, он может принимать `self` тремя способами: по значению (`self`), по изменяемой ссылке (`&mut self`) или по неизменяемой ссылке (`&self`).

Ровно этим и отличаются три стандартных типажа замыканий:

### `FnOnce` (принимает `self`)
Самый базовый типаж. При вызове метод принимает саму структуру замыкания по значению (`self`), то есть забирает владение ею. Если внутри замыкания захваченный `String` или `Vec` передаётся по значению в другую функцию или удаляется через `drop`, второй раз вызвать такое замыкание уже не выйдет: переменных внутри него просто не осталось. Поэтому `FnOnce` можно вызвать только один раз.

### `FnMut` (принимает `&mut self`)
Реализуется для замыканий, которые меняют захваченные переменные, но оставляют их внутри себя. Вызывать такое замыкание можно сколько угодно раз (например, счётчик или аккумулятор в цикле), но сама переменная замыкания должна быть объявлена с `mut`. Запустить его параллельно из нескольких потоков без мьютекса не выйдет.

### `Fn` (принимает `&self`)
Реализуется для замыканий, которые только читают захваченные данные по ссылке `&self` (или вообще ничего не захватывают, как обычные функции `fn`). Их можно вызывать многократно и безопасно разделять между потоками.

### Как не путать их в ограничениях `where`

Между этими тремя типажами в стандартной библиотеке выстроена прямая иерархия: `Fn` наследует `FnMut`, а `FnMut` наследует `FnOnce`.

На практике это часто путает при написании сигнатур собственных функций, поэтому проще запомнить правило со стороны того, кто функцию вызывает:

- Если ваша функция просит в аргументах **`FnOnce`** (как это делает `Option::unwrap_or_else`), в неё можно передать **вообще любое замыкание** или функцию. Ведь если замыкание умеет вызываться много раз (`Fn` или `FnMut`), то вызвать его один раз точно не проблема.
- Если функция требует **`FnMut`** (например, `Iterator::map` или `Vec::retain`), ей подойдут `FnMut` и `Fn`, но одноразовый `FnOnce` компилятор уже не пропустит.
- Если функция требует **`Fn`**, условие самое жёсткое: подойдут только замыкания, которые ничего у себя внутри не меняют, и обычные функции `fn`.

## 5. Передача, возврат и хранение в структурах

Раз у каждого замыкания свой безымянный тип структуры, написать его явно в сигнатуре функции не получится. Вместо этого используют дженерики или `impl Trait`:

```rust
fn execute(mut action: impl FnMut()) {
    action();
}
```

При возврате замыкания из функции работает тот же `impl Trait`, но здесь почти всегда обязательно слово `move` (иначе замыкание попытается унести с собой ссылку на локальные переменные функции, которые умрут при выходе из `create_adder`):

```rust
fn create_adder(x: i32) -> impl Fn(i32) -> i32 {
    move |y| x + y
}
```

> [!WARNING]
> **Ограничение `impl Trait` при возврате:** синтаксис `-> impl Fn(...)` означает статическую диспетчеризацию. Компилятор должен подставить туда ровно одну конкретную структуру замыкания. Если функция в разных ветках `if / else` пытается вернуть разные замыкания, код не соберётся:
> 
> ```rust
> fn returns_closure(cond: bool) -> impl Fn(i32) -> i32 {
>     if cond {
>         |x| x
>     } else {
>         |x| x * 3 // ОШИБКА: у двух замыканий разные анонимные типы!
>     }
> }
> ```
> 
> Когда выбор замыкания зависит от рантайм-условий, его оборачивают в трейт-объект `Box<dyn Fn(...)>` (или приводят к указателю `fn(i32) -> i32`, если переменные не захватываются):
> 
> ```rust
> fn returns_closure(cond: bool) -> Box<dyn Fn(i32) -> i32> {
>     if cond {
>         Box::new(|x| x)
>     } else {
>         Box::new(|x| x * 3)
>     }
> }
> ```

Та же самая развилка возникает, когда нужно сохранить колбэк в поле структуры:

1. **Через дженерик `struct Runner<F: Fn()> { action: F }`:** структура замыкания встраивается прямо внутрь памяти `Runner` без аллокаций в куче, а вызов может быть заинлайнен компилятором. Цена за скорость: каждый экземпляр `Runner` привязан к одному конкретному замыканию.
2. **Через `struct Runner { action: Box<dyn Fn()> }`:** замыкание уходит в кучу, а в `Runner` лежит толстый указатель (адрес данных + таблица виртуальных методов `vtable`). Зато в один вектор `Vec<Box<dyn Fn()>>` можно сложить десятки разных обработчиков событий.

## 6. Времена жизни на лету (`for<'a>` и ограничения типажей)

Напоследок разберём случай, где замыкания пересекаются с временами жизни ссылок.

Представьте функцию, которая создаёт внутри себя временную строку, передаёт ссылку на неё в замыкание и тут же эту строку удаляет. Если попробовать вынести время жизни `'a` в параметры самой функции (`fn run_with_ref<'a, F>(f: F)`), компилятор выдаст ошибку: параметр `'a` задаётся снаружи вызывающим кодом, а он понятия не имеет о локальной переменной внутри `run_with_ref`.

Чтобы сказать компилятору: *«это замыкание готово принять ссылку с любым временем жизни, которое появится только в момент вызова»*, используется синтаксис Higher-Rank Trait Bounds (HRTB) с ключевым словом `for<'a>`:

```rust
fn run_with_ref<F>(f: F)
where
    F: for<'a> Fn(&'a str),
{
    let local = String::from("локальный буфер");
    f(&local); // ссылка живёт только внутри этой функции
}
```

Для простых аргументов вроде `F: Fn(&str)` компилятор подставляет `for<'a>` автоматически. А вот когда замыкание принимает ссылку и возвращает другую ссылку, привязанную к тому же локальному времени жизни (`for<'a> Fn(&'a str) -> &'a str`), без явной записи уже не обойтись.

Попробуйте поэкспериментировать со всеми этими случаями:


### 💻 Замыкания в Rust


#### Шаг 1

```rust
fn call_with_five(f: fn(i32) -> i32) {
    println!("Вызов fn pointer: {}", f(5));
}

fn main() {
    // 1. Указатель на обычную функцию
    fn add_one(x: i32) -> i32 { x + 1 }
    call_with_five(add_one);
    
    // 2. Замыкание с захватом внешнего окружения
    let coefficient = 10;
    let closure = |x| x * coefficient;
    
    // call_with_five(closure); // Ошибка! Замыкание с состоянием не приводится к fn pointer.
    println!("Вызов замыкания: {}", closure(5));
}
```

**Указатели на функции и замыкания**
- Указатель на функцию `fn` является "тонким" указателем: он хранит только адрес машинного кода.
- Замыкание (анонимная функция) может захватывать внешние переменные и нести с собой состояние.
- Замыкания получают уникальный анонимный тип, генерируемый компилятором.


#### Шаг 2

```rust
fn call_fn<F: Fn()>(f: F) { f(); }
fn call_fn_mut<F: FnMut()>(mut f: F) { f(); }
fn call_fn_once<F: FnOnce()>(f: F) { f(); }

fn main() {
    let mut greeting = "Hello".to_string();
    
    // Fn: только читает окружение
    let closure_fn = || println!("Fn: {}", greeting);
    call_fn(closure_fn);
    
    // FnMut: изменяет окружение
    let closure_mut = || {
        greeting.push_str(" World");
        println!("FnMut: {}", greeting);
    };
    call_fn_mut(closure_mut);
    
    // FnOnce: забирает владение greeting
    let closure_once = move || {
        let owned = greeting;
        println!("FnOnce: {}", owned);
    };
    call_fn_once(closure_once);
    // call_fn_once(closure_once); // Ошибка! Замыкание closure_once уже было вызвано и перемещено.
}
```

**Трейты Fn, FnMut и FnOnce**
- `Fn`: обращается к данным по обычной ссылке `&self`. Можно вызывать параллельно из разных потоков.
- `FnMut`: меняет данные по изменяемой ссылке `&mut self`.
- `FnOnce`: забирает захваченные данные по значению (`self`). Можно вызвать только один раз.


#### Шаг 3

```rust
fn get_counter(mut start: u32) -> impl FnMut() -> u32 {
    move || {
        start += 1;
        start
    }
}

fn main() {
    let mut next = get_counter(100);
    println!("Счетчик: {}", next());
    println!("Счетчик: {}", next());
}
```

**Возврат замыканий из функций**
- Так как типы замыканий анонимны, мы используем синтаксис `impl Trait`.
- Мы обязаны использовать ключевое слово `move`, чтобы передать владение захваченными переменными.
- Иначе возвращаемое замыкание ссылалось бы на локальные переменные функции, которые уничтожаются при выходе.


#### Шаг 4

```rust
fn process_borrowed<F>(f: F)
where
    F: for<'a> Fn(&'a str),
{
    let local_string = String::from("Локальные данные");
    f(&local_string); // Ссылка живет только внутри функции
}
fn main() {
    // Замыкание принимает ссылку на строку, время жизни которой определено внутри process_borrowed
    let print_len = |s: &str| println!("Длина строки: {}", s.len());
    process_borrowed(print_len);
}
```

**2. Что сделает компилятор по умолчанию (без слова `move`), если внутри замыкания у внешнего вектора вызывается `list.push(42)`?**

- [ ] Скопирует весь вектор `list` внутрь замыкания
- [ ] Заберёт вектор `list` во владение навсегда, удалив его после первого вызова
- [ ] Захватит изменяемую ссылку `&mut list`, заблокировав доступ к `list` снаружи на время жизни замыкания

**3. Зачем перед замыканием пишут `move`, если внутри него внешняя переменная только читается (например, при передаче в `std::thread::spawn`)?**

- [ ] Чтобы заставить замыкание перенести переменную внутрь себя по значению, иначе оно возьмёт ссылку `&T` на стек функции, которая может завершиться раньше потока
- [ ] Чтобы ускорить чтение переменной за счёт отключения проверок границ массива
- [ ] Ключевое слово `move` автоматически оборачивает все переменные в `Arc` и `Mutex`

**4. Что произойдёт с переменной `let count: i32 = 10;`, если использовать её внутри замыкания с `move`: `let f = move || println!("{}", count);`?**

- [ ] Обратиться к `count` снаружи после создания замыкания будет нельзя (ошибка borrow checker)
- [ ] Внутрь замыкания попадёт побитовая копия числа, а переменная `count` снаружи останется полностью рабочей и доступной
- [ ] Код не скомпилируется, так как `move` запрещено использовать с примитивными типами

**5. Во что компилятор Rust превращает замыкание при сборке и чему равен его размер на стеке?**

- [ ] В динамический объект в куче (heap), размер которого всегда равен 16 байтам
- [ ] В анонимную структуру, полями которой становятся захваченные переменные (или ссылки на них), а размер равен сумме размеров этих полей
- [ ] В глобальную функцию со статическими переменными в сегменте `.bss`

**6. Как методы типажей `FnOnce`, `FnMut` и `Fn` принимают саму структуру замыкания (`self`)?**

- [ ] `FnOnce` принимает `self` по значению, `FnMut` — по изменяемой ссылке `&mut self`, `Fn` — по неизменяемой ссылке `&self`
- [ ] `FnOnce` принимает `&self`, `FnMut` принимает `&mut self`, а `Fn` принимает `self` по значению
- [ ] Все три типажа принимают `&self`, а разница проверяется только в рантайме

**7. Если функция объявлена как `fn run<F: FnOnce()>(action: F)`, какие замыкания в неё можно передать?**

- [ ] Строго только те замыкания, которые уничтожают свои переменные при вызове
- [ ] Только `FnOnce` и `FnMut`, но не `Fn`
- [ ] Вообще любые замыкания (`FnOnce`, `FnMut`, `Fn`) и обычные указатели на функции `fn`

**8. Почему функция с сигнатурой `fn make_op(flag: bool) -> impl Fn(i32) -> i32` не скомпилируется, если в ветке `if` возвращается `|x| x + 1`, а в `else` — `|x| x * 2`?**

- [ ] Ключевое слово `impl` нельзя использовать в позиции возвращаемого значения
- [ ] Каждое замыкание получает свой уникальный анонимный тип структуры, а `-> impl Trait` требует возвращать один и тот же конкретный тип во всех ветках
- [ ] Оба замыкания должны обязательно захватывать переменную `flag`

**9. В чём главный компромисс между хранением замыкания в структуре через дженерик `struct Runner<F: Fn()> { f: F }` и через `Box<dyn Fn()>`?**

- [ ] Дженерик встраивает замыкание прямо в структуру без аллокации в куче и позволяет инлайнить вызов, а `Box<dyn Fn()>` выделяет память в куче, но позволяет хранить разные замыкания в одном типе или векторе
- [ ] Вариант с дженериком позволяет менять замыкание на другое во время работы программы, а `Box<dyn Fn()>` — нет
- [ ] Через дженерик можно хранить только указатели `fn`, без захваченных переменных

**10. Для чего в ограничении `where F: for<'a> Fn(&'a str)` используется конструкция `for<'a>` (Higher-Rank Trait Bounds)?**

- [ ] Она запускает замыкание в цикле для каждой подстроки
- [ ] Она требует, чтобы переданная в замыкание строка жила до самого конца программы (`'static`)
- [ ] Она говорит компилятору, что замыкание готово принять ссылку с любым временем жизни, которое появится только внутри функции в момент вызова
