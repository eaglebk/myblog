<p><strong>Перечисления (Enums)</strong> в Rust — это тип данных, который позволяет описать сущность, принимающую одно из нескольких возможных значений (вариантов).</p>
<p>Если вы раньше программировали, например, на Java или C++, то наверняка пользовались enums для создания списка констант (например, дней недели). Но в Rust перечисления намного мощнее! Они позволяют хранить разнородные данные внутри каждого варианта, благодаря чему код становится чистым и безопасным.</p>

<p>В отличие от многих других языков, где перечисления — это просто список именованных целых чисел, в Rust варианты enums могут содержать в себе данные различного типа и структуры. Один <code>enum</code> может содержать три вида вариантов:</p>
<ol>
<li><strong>Юнит-варианты:</strong> без связанных данных (аналогично юнит-структурам).</li>
<li><strong>Кортежные варианты:</strong> со связанными безымянными данными в круглых скобках (аналогично структурам-кортежам).</li>
<li><strong>Структурные варианты:</strong> с именованными полями в фигурных скобках <code>{}</code> (аналогично обычным структурам).</li>
</ol>
<p>Давайте посмотрим, как объявляются варианты, что такое незаселенный тип и как извлечь данные с помощью <code>match</code> на интерактивных слайдах ниже:</p>
### 💻 Работа с перечислениями в Rust


#### Шаг 1


```rust
#[allow(dead_code)]
#[derive(Debug)]
enum WebEvent {
    // Юнит-вариант (без связанных данных)
    PageLoad,
    // Кортежный вариант (со связанными безымянными данными)
    KeyPress(char),
    // Структурный вариант (с именованными полями)
    Click { x: i64, y: i64 },
}

fn main() {
    let load = WebEvent::PageLoad;
    let press = WebEvent::KeyPress('q');
    let click = WebEvent::Click { x: 320, y: 240 };

    println!("load: {:?}", load);
    println!("press: {:?}", press);
    println!("click: {:?}", click);
}
```


**Варианты конструирования перечислений**
- Перечисления (enums) могут объединять данные разных форматов под одним типом.
- Юнит-варианты не несут связанных данных (`PageLoad`).
- Кортежные варианты хранят неименованные данные в круглых скобках (`KeyPress`).
- Структурные варианты хранят именованные поля в фигурных скобках (`Click`).


#### Шаг 2


```rust
// Определение незаселенного типа (uninhabited type)
// Перечисление без вариантов
#[allow(dead_code)]
enum EmptyEnum {}

fn main() {
    // Экземпляр EmptyEnum создать невозможно, так как нет вариантов!
    println!("EmptyEnum определен, но не может быть инициализирован.");
}
```


**Незаселенные типы (Uninhabited Types)**
- Перечисление без единого варианта называется незаселенным типом.
- Создать экземпляр такого типа в безопасном коде невозможно.
- Используется в системе типов для обозначения невозможных ситуаций (например, ошибки, которая никогда не произойдет).


#### Шаг 3


```rust
#[allow(dead_code)]
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
}

fn main() {
    let msg = Message::Move { x: 10, y: 20 };

    // Извлечение данных через сопоставление паттернов (pattern matching)
    match msg {
        Message::Quit => {
            println!("Событие выхода");
        }
        Message::Move { x, y } => {
            println!("Перемещение в координаты x = {}, y = {}", x, y);
        }
        Message::Write(text) => {
            println!("Запись сообщения: {}", text);
        }
    }
}
```


**Извлечение данных с помощью match**
- Механизм `match` гарантирует безопасный доступ к данным внутри вариантов enums.
- Компилятор Rust требует обязательной обработки всех вариантов перечисления (исчерпывающее сопоставление).
- Данные деструктурируются прямо в шаблоне ветки `match`.

<ul>
<li><strong>Шаг 1. Варианты конструирования:</strong> Мы создали перечисление <code>WebEvent</code>, демонстрирующее все три типа вариантов. Важная деталь: все поля и данные внутри вариантов перечисления <strong>автоматически являются публичными</strong>, писать <code>pub</code> перед ними не нужно.</li>
<li><strong>Шаг 2. Пустые перечисления:</strong> В Rust можно объявить <code>enum</code> вообще без вариантов (например, <code>enum EmptyEnum {}</code>). Создать объект такого типа в обычном коде невозможно. Зачем это нужно? Обычно так помечают состояния, которые никогда не должны произойти физически, помогая компилятору оптимизировать проверки.</li>
<li><strong>Шаг 3. Достаем данные (Pattern Matching):</strong> Так как разные варианты перечисления могут содержать абсолютно разные типы данных, компилятор не разрешит обратиться к ним напрямую. Нам нужно проверить, какой именно вариант сейчас активен. Самый удобный способ сделать это — конструкция <code>match</code>.</li>
</ul>
<blockquote><p><strong>Важная деталь:</strong> Конструкция <code>match</code> в Rust является исчерпывающей (exhaustive). Это означает, что компилятор выдаст ошибку, если хотя бы один из вариантов enums не будет обработан в ветках <code>match</code>.</p>
</blockquote><hr>

### 📝 Перечисления в Rust

**1. Как ещё называют перечисления (Enums) в теории типов?**

- [ ] Тип-произведение (product type)
- [x] Тип-сумма (sum type) или тегированное объединение (tagged union)
- [ ] Динамический интерфейс (dynamic interface)
- [ ] Абстрактный класс (abstract class)

> 💡 *Перечисления представляют собой типы-суммы (sum types) или tagged unions, так как значением перечисления является один (и только один) из его вариантов.*


**2. Какая видимость у полей (связанных данных) внутри вариантов перечисления по умолчанию?**

- [ ] Они автоматически являются приватными (private)
- [x] Они автоматически являются публичными (public)
- [ ] Их видимость зависит от видимости самого перечисления
- [ ] Требуется явно указывать ключевое слово `pub` перед каждым полем варианта

> 💡 *В отличие от структур, поля и связанные данные внутри вариантов перечисления в Rust автоматически являются публичными.*


**3. Какой из вариантов перечисления `enum Foo { A, B(u32), C { val: bool } }` является структурным вариантом?**

- [ ] A
- [ ] B(u32)
- [x] C { val: bool }
- [ ] Ни один из перечисленных

> 💡 *Вариант `C` с именованными полями в фигурных скобках является структурным вариантом, аналогично структуре с именованными полями.*


**4. Что представляет собой незаселенный тип (uninhabited type) в виде enum?**

- [ ] Перечисление, у которого все варианты помечены как устаревшие (deprecated)
- [x] Перечисление, которое вообще не содержит ни одного варианта
- [ ] Перечисление, содержащее только пустые юнит-варианты
- [ ] Специальное перечисление `Option::None`

> 💡 *В Rust перечисление может быть объявлено без вариантов (например, `enum Empty {}`). Такой тип называют незаселенным (uninhabited), поскольку невозможно создать экземпляр этого типа.*


**5. Как безопасно извлечь связанные данные из варианта перечисления?**

- [ ] С помощью приведения типов `as`
- [x] С помощью механизма сопоставления паттернов (pattern matching), например, через `match`
- [ ] С помощью прямого обращения через точку к имени варианта (например, `event.KeyPress.0`)
- [ ] Связав данные с глобальной переменной

> 💡 *Единственный безопасный способ получить доступ к данным внутри enums в Rust — проверить, какой вариант сейчас активен, с помощью сопоставления шаблонов (`match` или `if let`).*
