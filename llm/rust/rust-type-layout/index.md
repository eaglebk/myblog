<ul>
<li><strong>Управление памятью:</strong> Компилятор Rust автоматически рассчитывает и задает типу такие размеры (<code>size</code>) и выравнивание (<code>alignment</code>), которые гарантированно удовлетворяют техническим требованиям всех его внутренних полей на целевой архитектуре процессора.</li>
<li><strong>Паддинг (Padding):</strong> Компилятор имеет право автоматически вставлять неявные байты заполнения (паддинг) в структуру для обеспечения корректного выравнивания данных в памяти.</li>
<li><strong>Переупорядочивание полей:</strong> По умолчанию Rust <strong>не гарантирует</strong> сохранение порядка полей, написанного в коде. Компилятор оставляет за собой право произвольно менять порядок полей в кортежах, структурах и перечислениях для оптимизации размера и минимизации паддинга.</li>
</ul>
<p>Давайте изучим выравнивание, размеры типов, использование атрибутов представления <code>#[repr(...)]</code> и работу с тегами перечислений на интерактивных слайдах ниже:</p>
### 💻 Расположение типов в памяти в Rust


#### Шаг 1


```rust
use std::mem::{size_of, align_of};

#[allow(dead_code)]
struct Foo {
    a: u8,
    b: u32,
    c: u16,
}

fn main() {
    println!("Размер Foo: {} байт", size_of::<Foo>());
    println!("Выравнивание Foo: {} байт", align_of::<Foo>());
    
    // Если бы поля лежали в памяти строго по порядку (a, b, c):
    // 1 байт (a) + 3 байта паддинга + 4 байта (b) + 2 байта (c) + 2 байта паддинга = 12 байт.
    // Однако компилятор Rust переупорядочил поля в памяти (b, c, a):
    // 4 байта (b) + 2 байта (c) + 1 байт (a) + 1 байт паддинга = 8 байт!
}
```


**Выравнивание и размер по умолчанию**
- Компилятор Rust автоматически вставляет байты заполнения (padding) для правильного выравнивания.
- По умолчанию Rust свободно меняет порядок полей в памяти для минимизации размера структуры.
- Для `Foo` размер уменьшается с 12 до 8 байт благодаря оптимизации переупорядочивания полей.


#### Шаг 2


```rust
use std::mem::size_of;

#[repr(C)]
#[allow(dead_code)]
struct StructC {
    a: u8,
    b: u32,
    c: u16,
}

#[repr(align(16))]
#[allow(dead_code)]
struct StructAlign {
    a: u32,
}

#[repr(transparent)]
#[allow(dead_code)]
struct Wrapper(u32);

fn main() {
    println!("Размер StructC (repr(C)): {} байт", size_of::<StructC>());
    println!("Размер StructAlign (repr(align(16))): {} байт", size_of::<StructAlign>());
    println!("Размер Wrapper (repr(transparent)): {} байт", size_of::<Wrapper>());
}
```


**Атрибуты представления #[repr(...)]**
- `#[repr(C)]` выстраивает поля строго по порядку объявления (как в C/C++), запрещая переупорядочивание.
- `#[repr(align(N))]` задает минимальное выравнивание структуры в памяти (в байтах).
- `#[repr(transparent)]` гарантирует, что структура-обертка имеет точно такое же представление, как и ее единственное поле.


#### Шаг 3


```rust
#[repr(u32)] // Задаем тип тега (дискриминанта) в памяти как u32
#[allow(dead_code)]
enum Status {
    Active = 42,
    Inactive = 24,
    Pending = 134,
}

fn main() {
    let val = Status::Active;
    
    // Приведение перечисления к целому числу с помощью оператора `as`
    let num = val as u32;
    
    println!("Тег Status::Active в памяти равен: {}", num);
}
```


**Дискриминанты перечислений**
- Мы можем явно задавать числовые значения (дискриминанты) вариантам enums.
- Атрибут `#[repr(u32)]` (или другие целочисленные типы) фиксирует тип хранения тега в памяти.
- Варианты можно приводить к соответствующему числу с помощью оператора `as`.

<ol>
<li>
<p><strong>Шаг 1. Выравнивание и размер по умолчанию:</strong></p>
<ul>
<li>Каждому типу данных требуется выравнивание в памяти: адрес начала данных должен быть кратен выравниванию типа (обычно степени двойки: 1, 2, 4, 8 байт).</li>
<li>Из-за этого между полями могут образовываться пустые байты — <strong>паддинг</strong>.</li>
<li>По умолчанию (представление <code>repr(Rust)</code>) компилятор переупорядочивает поля структуры <code>Foo</code> так, чтобы они занимали 8 байт вместо 12 байт, размещая сначала самые строгие по выравниванию типы.</li>
</ul>
</li>
<li>
<p><strong>Шаг 2. Управление расположением данных с помощью атрибутов:</strong>
Для явного изменения логики размещения данных в памяти и обеспечения совместимости с другими языками используются специальные атрибуты представления:</p>
<ul>
<li><code>#[repr(C)]</code> — отключает оптимизацию переупорядочивания полей Rust и выстраивает их строго в том порядке, в котором они объявлены (совместимо с ABI языка C).</li>
<li><code>#[repr(align(N))]</code> — принудительно устанавливает минимальное выравнивание типа в памяти (например, 16 байт).</li>
<li><code>#[repr(transparent)]</code> — гарантирует, что тип имеет точно такое же представление в памяти и ABI, как и его единственное некорректное поле (используется для newtype-оберток).</li>
</ul>
</li>
<li>
<p><strong>Шаг 3. Явное тегирование перечислений (Enum Discriminants):</strong></p>
<ul>
<li>Для перечислений можно жестко фиксировать тип числового тега (дискриминанта) в памяти и присваивать явные числовые значения каждому варианту.</li>
<li>Это позволяет осуществлять безопасное приведение типов (кастинг) из перечисления в целочисленный тип с помощью ключевого слова <code>as</code>.</li>
</ul>
</li>
</ol>

### 📝 Type Layout в Rust

**1. Что по умолчанию делает компилятор Rust с порядком полей в структурах и кортежах?**

- [ ] Сохраняет порядок полей точно в таком виде, как они объявлены в коде
- [x] Может произвольно менять порядок полей для минимизации размера типа и паддинга
- [ ] Сортирует поля строго по алфавиту их имен
- [ ] Размещает все поля по случайным адресам в куче

> 💡 *По умолчанию Rust не гарантирует сохранение порядка полей (представление `repr(Rust)`). Компилятор оптимизирует расположение полей в памяти, переупорядочивая их для уменьшения размера и снижения затрат на выравнивание (паддинг).*


**2. Какой атрибут представления отключает оптимизацию переупорядочивания полей в Rust и выстраивает их в порядке объявления?**

- [ ] #[repr(align(8))]
- [ ] #[repr(transparent)]
- [x] #[repr(C)]
- [ ] #[repr(packed)]

> 💡 *Атрибут `#[repr(C)]` заставляет компилятор выстраивать поля в памяти точно в том порядке, в котором они были объявлены в исходном коде, обеспечивая совместимость с ABI языка C.*


**3. Зачем используется атрибут `#[repr(transparent)]`?**

- [ ] Чтобы сделать структуру полностью невидимой для отладчика
- [x] Чтобы гарантировать, что тип имеет точно такое же представление в памяти и ABI, как и его единственное не-нулевое поле
- [ ] Чтобы автоматически привести тип к строковому представлению
- [ ] Чтобы компилятор игнорировал правила выравнивания для этого типа

> 💡 *Атрибут `#[repr(transparent)]` применяется к newtype-структурам (содержащим ровно одно значащее поле), гарантируя, что обертка имеет точно такое же представление в памяти и ABI, как и лежащий внутри тип.*


**4. Каким образом в Rust можно получить числовой тег (дискриминант) варианта перечисления, если задано #[repr(u32)]?**

- [ ] С помощью метода `.to_u32()`
- [x] С помощью приведения типов через ключевое слово `as` (например, `val as u32`)
- [ ] Обратившись к полю `val.tag`
- [ ] Это невозможно сделать в безопасном коде

> 💡 *Если перечисление снабжено атрибутом целочисленного представления (например, `#[repr(u32)]`), его варианты можно приводить к соответствующему числу с помощью оператора `as`.*


**5. Что такое паддинг (Padding) в контексте расположения данных в памяти?**

- [x] Неявные байты заполнения, вставляемые компилятором для обеспечения корректного выравнивания полей
- [ ] Специальный тип данных для работы со строками
- [ ] Процесс копирования структуры из стека в кучу
- [ ] Очистка неиспользуемой памяти сборщиком мусора

> 💡 *Паддинг — это пустые байты-заполнители, которые компилятор автоматически вставляет между полями структуры или в конце, чтобы каждое поле начиналось с адреса, кратного его выравниванию.*
